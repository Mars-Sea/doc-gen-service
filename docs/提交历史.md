# 提交历史

按时间正序记录本次会话的改动。

## 一、模板寻址收敛（2026-10-02）

### 阶段 1：建立命名规则模块

- **新增 `template/TemplateName` 及其测试（35 例）**——把「什么名字能用、什么格式配什么文档」收敛为唯
  一一份规则，用不可变值对象表达，`parse()` 产出即合法。字符规则采用白名单（`\p{L}\p{N}_.-`）取代原
  黑名单，补上被漏掉的 Windows 盘符冒号；中文模板名保持合法。行为变化：`.xls` 由放行改为拒绝（EasyExcel
  4.0.1 技术上支持，但上传入口与列表入口均不接收，放行是死路）。

### 阶段 2：建立读侧与写侧模块

- **新增 `template/TemplateRepository`（`locate` / `read` / `list`）与 `template/TemplateWriter`
  （`upload` / `delete`）**——`TemplateName` 的 35 例 + `TemplateRepositoryTest` + `TemplateWriterTest`
  共 156 例全绿。读侧持有模板目录配置，写侧通过 `resolveForWrite` 取路径，基路径读法只有一份。

### 阶段 3：替换调用点并删除旧模块

- **`WordService` / `ExcelService` 改走 `TemplateRepository`，构造参数分别 3→2、2→1**——原先二者各自拼
  接 `templatePath` 并各自判断文件存在；`TemplateController` 四个端点改走读写两侧。
- **删除 `service/TemplateService.java`（206 行）、`util/TemplateValidationUtil.java`（80 行）及其测试
  （共 362 行测试迁移后删除）**——寻址规则已并入 `TemplateName`，职责已拆到读写两侧。
- **迁移 5 个穿越接缝的测试**（`WordServiceTest` 3 例、`ExcelServiceTest` 2 例）至新测试类——接口即测试
  面，同一事实不在三处重复锁定。新增「上传→寻址闭环」不变量断言，锁住「凡能落盘的名字一定能在读侧被合法解
  析」。

### 阶段 4：固化成果

- **`mvn test` 156 例全绿，`mvn spotless:check` 通过。**
- 新增 `GLOSSARY.md`（模板、模板名、文档类型、模板读侧、模板写侧、渲染数据、载荷），`docs/决策记录.md`
  （10 项决策 + 3 项未纳入的已知缺陷）。

## 二、载荷设施与附件响应收敛（2026-10-02）

### 阶段 1：附件响应收敛（候选 1）

- **新增 `GeneratedDocumentResponse`**，`DocController` 四端点各从约 30 行降到 8 行，净减约 88 行。 事实核查确认 Go SDK 不读
  Content-Disposition，无兼容风险。补齐原先缺失的头语义测试：中文名百分号编码、空格编码为 `%20`、四种
  DocumentType 的 MediaType 与默认名、字符清洗、空内容拒绝、contentLength。

### 阶段 2：载荷遍历器与统一出口（候选 3 前半）

- **新增 `PayloadWalker` 与 `ConvertedImage`**，删除 `WordService` 内联遍历（约 50 行）。 遍历覆盖三类容器：嵌套 Map、
  Iterable、数组——数组是独立一支，Java 中数组不实现 Iterable，原先漏掉它导致 `items[0].logo` 被渲染成
  `Map.toString()`。
- **新增两个测试用例**（图片在 List 内、图片在数组内）。这两个用例揭示：POI 会按图片字节去重（相同字节的两张图只留一个
  picture part），且「图片在集合内」此前从未被任何测试验证过。

### 阶段 3：Excel 侧补齐（候选 3 后半）

- **`ExcelService` 的 `listData` 分支接入载荷转换，并支持二维码**：事实核查确认 EasyExcel 的列表填充与单值填充走同一条
  `fillImage` 链路，缺口在自身代码未转换。这是此前完全无测试覆盖的路径。
- **`QrCodePayloadConverter` 新增字节级出口 `convertToImage`**——二维码由 ZXing 本地生成、无 URL，无法走图片的 HTTP 下载
  链路。
- 新增 2 个测试：listData 内图片载荷、listData 内二维码载荷。

### 阶段 4：固化成果

- **`mvn test` 172 例全绿，`mvn spotless:check` 通过。**
- 更新 `GLOSSARY.md`（载荷遍历器、载荷转换结果、生成的文档响应、列表数据）与 `docs/决策记录.md`。
